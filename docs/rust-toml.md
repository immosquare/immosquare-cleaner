# Rust and TOML formatting with rustfmt and taplo

immosquare-cleaner formats Rust files with rustfmt and TOML files (`Cargo.toml`, `rustfmt.toml`, `pyproject.toml`, any `.toml`) with taplo. Both follow the edited project's own configuration where it exists. This page covers what each tool reads, the defaults immosquare-cleaner applies, and how to install them.

## Rust files: rustfmt with the project's edition and configuration

Every `.rs` file goes through rustfmt, with three settings resolved from the project the file belongs to:

| Setting       | How immosquare-cleaner resolves it                                                                                                                                                                                                  |
| ------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Edition       | Read from the closest `Cargo.toml` that declares one. A workspace member using `edition.workspace = true` is followed up to the workspace root. `2024` when no `Cargo.toml` declares an edition.                                    |
| Configuration | The closest `rustfmt.toml` or `.rustfmt.toml`, walking up from the file, then the user's global rustfmt configuration in the home folder, `~/.config/rustfmt/` or `~/Library/Application Support/rustfmt/`.                         |
| Indentation   | 2 spaces when no configuration file exists. A project `rustfmt.toml` always wins, so a project that wants rustfmt's default 4 spaces only needs one.                                                                                |

The file is piped through rustfmt's stdin rather than passed as a path. Given a path, rustfmt also rewrites every child module a `mod foo;` declaration points to, which would reformat files the agent never touched. On a syntax error, rustfmt's message is printed and the file is left untouched.

```diff
 use std::collections::HashMap;
-fn count(words:&[&str])->HashMap<&str,usize>{
-let mut map=HashMap::new();
-    for w in words { *map.entry(*w).or_insert(0)+=1; }
-  map
+fn count(words: &[&str]) -> HashMap<&str, usize> {
+  let mut map = HashMap::new();
+  for w in words {
+    *map.entry(*w).or_insert(0) += 1;
+  }
+  map
 }
```

Install rustfmt with `rustup component add rustfmt`. When it is missing, immosquare-cleaner prints that command and leaves `.rs` files as they are.

## TOML files: taplo with aligned keys

Every `.toml` file goes through taplo with four options: the `=` of consecutive keys are aligned, nested arrays are indented with 2 spaces, lines are never wrapped, and multi-line arrays (workspace `members`, `features`) keep the layout they were written with. Unlike rustfmt, taplo ignores a `.taplo.toml` in the project: the same layout applies to every repository.

```diff
 [package]
-name="demo"
+name    = "demo"
 version = "0.1.0"
-edition="2021"
+edition = "2021"
 [dependencies]
-serde={version="1",features=["derive"]}
+serde = { version = "1", features = ["derive"] }
```

Install taplo with `brew install taplo`. When it is missing, immosquare-cleaner prints that command and leaves `.toml` files as they are.

## Rust repositories cleaned in one run

`immosquare-cleaner .` at the root of a Rust or Tauri repository formats the `.rs` and `.toml` files listed by `git ls-files`, and skips `target/` at any depth along with the generated Tauri folders `src-tauri/gen` and `src-tauri/permissions/autogenerated`. The other rules of a repository clean are described in [Cleaning a whole repository](repository.md).
